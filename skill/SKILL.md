# Notion 无限电台：生产新集

你负责把用户 Notion 知识库里的笔记改写成适合收听的中文播客脚本，写进电台仓库，推送后由 GitHub Actions 用 edge-tts 合成音频、发布 RSS 和网页播放器。你只写脚本和状态文件，不在本地合成音频。

## 前提

- 电台仓库（含 `podcast.json`、`tools/render.py`、`.github/workflows/publish.yml`）已克隆到当前工作目录，且你有推送权限。不在仓库里时，先问用户仓库地址并克隆。
- Notion 连接器可用。**只读 Notion，绝不修改。**
- 关键文件：
  - `podcast.json`：配置。`notion_root` 是知识库根页面，`per_run_minutes` 是每次产出的目标时长，`voices.A` 是候选人，`voices.B` 是面试官，音色可以在这里换。
  - `state/notion-index.json`：你维护的状态，结构见下文。
  - `docs/episodes.json`：已发布的集，由 Actions 写入，你只读。
  - `episodes/<id>/episode.json`：每集脚本，由你新建。

## 每次运行的流程

### 1. 同步与读取

`git pull`，然后读 `podcast.json`、`state/notion-index.json`、`docs/episodes.json`，以及 `episodes/` 下已有的 id 列表（包括 Actions 还没发布完的）。

### 2. 扫描 Notion

1. 用 notion-fetch 获取 `notion_root`，从中拿到各分类子页面；再逐个 fetch 分类页面，列出所有笔记页面（标题、id、所属分类）。
2. 获取最后编辑时间：用 notion-search，`page_url` 设为根页面，`page_size` 50，`max_highlight_length` 0。依次用“的”、各分类名作为 query 搜索，合并结果里的 `timestamp`。搜不到时间的页面，在真正要制作它时用 fetch 返回的 `page_last_edited_at` 补上。
3. 和 `state.pages` 对比，把页面分成三类：
   - **新增**：状态里没有。
   - **有更新**：状态里的 `last_edited` 早于当前时间，且距上次制作后有实质修改。
   - **未制作**：在状态里，但 `episodes` 为空。
4. 把扫描结果（新页面、新时间戳）写回 `state.pages`。

### 3. 选题

按 `per_run_minutes`（默认 60 分钟）挑出本次要做的集，按中文约 270 字一分钟估算时长。优先级：

1. 新增的页面。
2. 有更新的页面。修改较小的做 3 到 5 分钟的“快问快答”，只讲更新要点；改动大的换一种面试风格重做一集。
3. 体系内还没做过的页面。按分类轮转，不要连续两集都来自同一个分类；同一分类内按编号顺序。
4. 以上全部做完时，停止，并告诉用户“知识库已全部制作完毕”。用户说过内容耗尽后的扩展暂时不做，不要自行联网补充内容，也不要重复制作。

长笔记（正文超过约 8000 字）可以拆成上下两集，`id` 加 `-p1`、`-p2` 后缀。

### 4. 选体裁：技术内容一律用面试对话

技术笔记都做成**面试官与候选人的对话**。`B` 是面试官，`A` 是候选人（具体音色见 `podcast.json` 的 `voices`）。面试有几种风格，按内容挑最合适的，再轮换：

| 风格 | `style` 值 | 怎么问 | 时长 | 最适合 |
| --- | --- | --- | --- | --- |
| 标准技术面 | 标准技术面 | 从基础问起，每个回答都往深一层追问 | 12 到 18 分钟 | 原理类、对比类 |
| 手撕面 | 手撕面 | 让候选人口述实现思路，面试官挑 bug、问边界条件 | 10 到 15 分钟 | 算法、数据结构 |
| 系统设计面 | 系统设计面 | 给业务场景，候选人设计，面试官不断加约束（量级、故障、一致性） | 15 到 20 分钟 | 系统设计、分布式 |
| 源码深挖面 | 源码深挖面 | “读过某某源码吗？”，然后一层层往下问实现细节 | 12 到 18 分钟 | 源码精读、语言运行时 |
| 挑刺面 | 挑刺面 | 面试官质疑候选人的选型，候选人辩护，再修正 | 10 到 15 分钟 | 存在取舍的选型 |
| 快问快答 | 快问快答 | 短问题连发，候选人一两句作答 | 3 到 5 分钟 | 笔记的更新要点、短笔记 |

`format` 统一写 `面试问答`，`style` 写上表的值。规则：

- 本次产出里**不连续两集用同一风格**，并参考 `state.rotation.last_style`。
- 每个页面记录用过的风格，以后重做时换一种。

### 5. 写脚本：要像真的面试

先 fetch 页面全文，再写。**内容只能来自原文**：不编造数字、版本、出处，原文没有的不要补充。

**角色和节奏**

- 面试官说短句，通常 5 到 30 字：提问、追问、打断、加条件，或者简短回应（“嗯。”“然后呢？”“就这样？”）。面试官不讲课，也不夸张夸奖，最多说一句“可以”“答得还行”。
- 候选人负责大部分内容，但一次最多连说 3 句，每句不超过 60 字。说完就要被追问或回应，不能一口气讲完一个知识点。
- 开场一两句寒暄后直接提问，不念标题，不做节目介绍。

**真实感（每章至少用上两种）**

- 候选人先给直觉的、不完整的答案，被追问后补全。
- 卡壳和思考：“呃……我想一下。”，后面那句加 `"gap": 0.6` 到 `0.9`。
- 自我纠正：“不对，数组挪一下是线性的，得用双向链表。”
- 面试官打断：前一句以“——”结尾，打断的那句加 `"gap": 0.05`。
- 面试官给提示，或者加约束：“那我加个需求，要支持 TTL 过期。”
- 面试官抛出场景题，让候选人推演会发生什么。

候选人中途可以想错，但必须当场被纠正，最后的结论要和原文一致。

**把不能听的东西改成能听的**

- 表格改成面试官逐个维度追问、候选人对比作答，只挑关键的两三个维度。
- 代码不逐行念：面试官让候选人“说思路”，候选人讲数据结构和关键步骤，面试官再挑出原文提到的坑来问。
- mermaid 图、流程图改成候选人按顺序口述。
- 符号念成中文：`>` 写成“大于”，`++` 写成“加一”。英文术语保留原词，缩写第一次出现时顺口解释一句。

**朗读稿写法（edge-tts 的读法规律）**

- **数字写成汉字的读法**：“2023 年”写“二零二三年”，“95%”写“百分之九十五”，“5000 万”写“五千万”，“5 到 10”写“五到十”。阿拉伯数字会被当成一个词，读法常常不对。
- **复杂度说中文**：O(1) 写“常数时间”，O(N) 写“线性时间”，O(log N) 写“对数时间”。
- **不要单个字母**：中文音色会把单个字母读成怪音。“f 桶”改成“原来的频次桶”；变量名、字段名改成中文说法（minFreq 说成“最小频次”）。LRU、Redis、Count-Min Sketch 这种完整的英文词可以保留。
- **标点就是停顿**：逗号短停，句号、问号长停，省略号“……”约等于一个句号，适合犹豫和思考。破折号“——”不停顿，正好用在被打断的半句话末尾。
- **一句 12 到 22 个字最好**。超过 35 个字没有标点，一定要在意群之间加逗号，不然一口气读完，听着很赶。
- **读错的词**：词粘错了就加逗号或补字（“闭着眼”写“闭着眼睛”）；多音字读错就换同音字。
- 同一个人连续的几句（没有单独写 `gap`、`rate` 的）会合并成一次合成，最长 150 字，这样句间语调连贯。想让同一个人中间停顿久一点，就在后一句加 `gap`。
- 写完运行 `python3 tools/render.py --lint --only <id>`，把提醒逐条改掉再提交。

**语气词和书面语**

- 可以用“嗯”“呃”“对”“就是说”“其实”“你想啊”，每句最多一个，不要每句都加。
- 禁用书面连接词：“首先、其次、最后”“综上所述”“值得注意的是”。

**结构**

- 每集 5 到 9 章，每章 6 到 15 句。章节标题写成面试的环节，例如“追问：你这个 Put 有 bug”“压力题：半夜的全表扫描”。
- 最后一章：面试官让候选人总结，候选人用三四句收束，面试官点评一句，再顺口提一个下次要问的话题（来自原文“继续阅读”里的笔记）。
- 写完后自查一遍：逐条对照原文核对技术事实，删掉原文里没有的论断；再通读一遍，看哪里还像在念稿，改掉。

**可选的节奏字段**（加在单句上）

- `"gap": 秒数`：这句之前的停顿。每句首尾的静音会被裁掉，所以这就是实际停顿。默认换人 0.3 秒，换章 1.2 秒。
- `"rate": "+10%"`：这句说快一点，适合抢话或急着解释的时候；`"-5%"` 用于放慢思考。

### 6. 写入文件

在 `episodes/<id>/episode.json` 写入，格式如下：

```json
{
  "id": "2026-11-25-cache-eviction",
  "title": "面试：缓存满了该扔谁？从 LRU 一路问到 S3-FIFO",
  "description": "一两句话的节目简介，出现在播客 App 里。",
  "format": "面试问答",
  "style": "标准技术面",
  "sources": [
    {"title": "07-缓存淘汰结构LRU与LFU", "url": "Notion 页面 URL", "last_edited": "2026-11-25T02:43:29Z"}
  ],
  "chapters": [
    {"title": "章节标题", "lines": [
      {"speaker": "B", "text": "面试官的问题。"},
      {"speaker": "A", "text": "候选人说到一半——"},
      {"speaker": "B", "text": "面试官打断。", "gap": 0.05},
      {"speaker": "A", "text": "呃，我想一下。"},
      {"speaker": "A", "text": "思考后的回答。", "gap": 0.8}
    ]}
  ]
}
```

- `id` 格式为 `YYYY-MM-DD-英文短词`，只能用小写字母、数字和连字符，且不能和已有的 id 重复。
- `speaker` 只能是 `A` 或 `B`。
- 不写 `seq`，脚本按 id 的字母顺序给新集依次编号，所以同一天的多集要让 id 的字母顺序和你想要的播放顺序一致。

然后更新 `state/notion-index.json`：

```json
{
  "pages": {
    "<notion 页面 id>": {
      "title": "07-缓存淘汰结构LRU与LFU",
      "category": "06-数据结构与算法",
      "url": "...",
      "last_edited": "2026-11-25T02:43:29Z",
      "episodes": [{"id": "2026-11-25-cache-eviction", "format": "面试问答", "style": "标准技术面", "made_from_edit": "2026-11-25T02:43:29Z"}]
    }
  },
  "rotation": {"last_style": "标准技术面", "last_category": "06-数据结构与算法"}
}
```

### 7. 提交与汇报

1. 用 `python3 -c "import json,sys;[json.load(open(p)) for p in sys.argv[1:]]" episodes/*/episode.json state/notion-index.json` 校验 JSON。
2. 提交并推送：`git add episodes state && git commit -m "新增 N 集：<标题们>" && git pull --rebase && git push`。
3. 推送会触发 Actions 渲染。能用 `gh run watch` 就等它跑完，确认成功；失败时读 `gh run view --log-failed`，修好再推。
4. 用一小段话向用户汇报：做了哪几集（标题、面试风格、预计时长），知识库还剩多少页没做，网页播放器地址（`site_url`）。

## 用户可以临时指定

- “做 3 集”“做 2 小时”：覆盖 `per_run_minutes`。
- “做某某笔记”“只做 Go 分类”：直接按指定选题，跳过优先级。
- “换成系统设计面”：指定面试风格。
- “换面试官的声音”：改 `podcast.json` 里 `voices.B.voice`，同时设置 `rate` 和 `pitch`：女声音高 `-2Hz`、男声 `-4Hz` 能去掉电子味，语速一般用 `+0%`；`en-US-BrianMultilingualNeural` 这类多语言音色说中文时原速偏慢，用 `+16%` 左右。只影响之后渲染的集。
- “重做某一集”：改写对应的 `episode.json`，同时从 `docs/episodes.json` 删掉这一集的条目、删掉 `docs/chapters/<id>.json`，再提交。Actions 会用同一个 id 重新渲染并覆盖原音频。
